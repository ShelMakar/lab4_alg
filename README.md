# Лабораторная работа 4. Алгоритмический мини-пакет

Устанавливаемый пакет `algopack`: рекуррентная задача (быстрая степень), две сортировки, структура данных (очередь), генераторы тестовых наборов, benchmark с отчётом и консольный интерфейс.

## Установка

Для работы необходим Python 3.10 или выше.

Клонировать репозиторий:

```bash
git clone <ссылка на репозиторий>
cd <папка репозитория>
```

Создать и активировать виртуальное окружение:

```bash
python -m venv .venv
```

```bash
.venv\Scripts\activate
```

(Linux и macOS: `source .venv/bin/activate`)

Установить пакет в режиме разработки вместе с инструментами проверки:

```bash
pip install -e ".[dev]"
```

После установки доступна команда `algopack`

Для проверок качества кода:

```bash
pre-commit install
```

## Рекуррентная задача: быстрая степень

Вычисляется `number ** exp` для целых `number` и `exp >= 0` двумя способами.

| Функция | Способ | Идея |
|---|---|---|
| `fast_pow_rec(number, exp)` | рекурсия | чётная степень: `half = a^(e/2)`, результат `half * half`; нечётная: `a * a^(e-1)` |
| `fast_pow_loop(number, exp)` | цикл | двоичное разложение показателя: на каждом шаге квадрат основания, умножение на результат при единичном бите |

**Недопустимый ввод.** Проверка выполняется в обеих функциях:

| Ситуация | Исключение |
|---|---|
| `number` или `exp` не `int` (в том числе `float`, `str`, `None`, `bool`) | `NotIntError` (наследник `TypeError`) |
| `exp < 0` | `IncorrectExpError` (наследник `ValueError`) |

`0 ** 0` по соглашению возвращает `1`.

### Ограничение рекурсии Python

В CPython глубина рекурсии ограничена (`sys.getrecursionlimit()`, по умолчанию **1000** кадров). Рекурсивная версия делает не более `2·log2(exp) + 1` вложенных вызовов, поэтому `RecursionError` возможен только при показателях порядка 2^500 и выше, то есть на практике почти недостижим, но граница существует. Итеративная версия от лимита не зависит. Лимит можно поднять через `sys.setrecursionlimit`, но это не отменяет риск переполнения стека C, и в пакете лимит не изменяется. CLI перехватывает `RecursionError` и печатает понятное сообщение.

| Версия | Время | Доп. память |
|---|---|---|
| `fast_pow_rec` | O(log exp) умножений | O(log exp) (стек вызовов) |
| `fast_pow_loop` | O(log exp) умножений | O(1) (кроме самого результата) |

Для обычного возведения в цикле нужно `exp` умножений, а здесь около `log2(exp)`. Оценка дана в числе умножений; для очень больших чисел само умножение дорожает с ростом разрядности.

## Сортировки

Обе функции **возвращают новый список**, входной список **не изменяется**. Внутри не используются `sorted` и `list.sort`.

| Функция | Алгоритм |
|---|---|
| `selection_sort(items)` | сортировка выбором |
| `quick_sort(items)` | быстрая сортировка, опорный элемент в середине, разбиение на три части (меньше / равно / больше) |

Поддерживаются пустой список, один элемент, дубликаты и отрицательные числа.

**Поведение при неверном типе.**

- Ожидается `list`. Если передан объект, который нельзя обойти (`None`, число), будет `TypeError`.
- Если элементы несравнимы между собой (например, `[1, "a"]`), будет `TypeError` от операции сравнения. У списка из 0 или 1 элемента сравнений нет, поэтому ошибки тоже нет.
- Поведение для других итерируемых (`str`, `tuple`, множества) не гарантируется.

### Сложность

| Алгоритм | Лучший | Средний | Худший | Доп. память |
|---|---|---|---|---|
| `selection_sort` | O(n²) | O(n²) | O(n²) | O(n) (копия) |
| `quick_sort` | O(n log n) | O(n log n) | O(n²) | O(n) в среднем, в худшем случае больше |

- **Selection sort** всегда делает порядка n²/2 сравнений независимо от входа, поэтому время почти не зависит от типа набора.
- **Quick sort:** на каждом уровне рекурсии обрабатывается суммарно n элементов, уровней порядка log n при удачном опорном. Опорный из середины даёт хорошее поведение на отсортированных и обратных входах. Трёхстороннее разбиение сводит дубликаты к одному проходу, поэтому набор с малым числом различных значений не вырождается. Худший случай (опорный постоянно оказывается крайним значением) возможен на специально подобранных входах: тогда время O(n²), а глубина рекурсии порядка n, и действует ограничение рекурсии Python (см. выше).
- Память `quick_sort`: функция строит новые списки на каждом уровне, поэтому в среднем это O(n), а при вырождении существенно больше.

## Структура данных: очередь `Queue`

FIFO на **кольцевом буфере**: массив `_buf`, индекс головы `_head`, размер `_size`. Ёмкость начинается с 4 и удваивается при заполнении (буфер «выпрямляется» при росте). Ёмкость не уменьшается.

| Операция           | Описание | Время                                             |
|--------------------|---|---------------------------------------------------|
| `add_queue(value)` | добавить в конец | O(1) амортизированно (O(n) если size == capasity) |
| `pop_queue()`      | извлечь из начала; пусто → `EmptyQueueError` | O(1)                                              |
| `next()`           | посмотреть следующий элемент без извлечения; пусто → `EmptyQueueError` | O(1)                                              |
| `len(q)`           | число элементов | O(1)                                              |
| `bool(q)`          | `True`, если очередь не пуста | O(1)                                              |

Память: O(n)

## Генераторы тестовых наборов

Все функции возвращают **новый** `list[int]`, принимают `n` и необязательный `seed`. Для случайности используется локальный `random.Random(seed)`, глобальное состояние генератора случайных чисел не затрагивается. Один `seed` даёт один и тот же результат; при `seed=None` результат не воспроизводим.

| Генератор | Описание |
|---|---|
| `random_list(n, seed)` | случайные значения из `[-n, n]` |
| `sorted_list(n, seed)` | те же значения, что у `random_list`, по возрастанию |
| `reversed_list(n, seed)` | те же значения по убыванию |
| `nearly_sorted(n, seed, swap_fraction=0.05)` | отсортированный список, в котором переставлено около `swap_fraction · n` пар элементов |
| `many_duplicates(n, seed, distinct=10)` | значения берутся из пула размером `distinct`, различных значений не более `distinct` |

Словарь `GENERATORS` связывает имена наборов (`random`, `sorted`, `reversed`, `nearly_sorted`, `many_duplicates`) с функциями.

## Benchmark

### Методика

- Для каждого типа входа и размера набор **генерируется один раз вне замера**.
- В каждом повторе алгоритм получает **независимую копию** `list(base)`; копия создаётся до запуска таймера.
- Время измеряется через `time.perf_counter`.
- **Повторов не менее 5** (CLI отклоняет меньшее значение).
- Размеры по умолчанию: 100, 1 000, 10 000. Для медленных алгоритмов можно ограничить размер параметром `--max-size`.
- Для каждой точки сохраняются `min`, `max`, `median`, `mean`. В выводах используется **медиана**: она устойчива к случайным выбросам (сборка мусора, фоновая нагрузка).


### Запуск

```bash
algopack benchmark --sizes 100 1000 10000 --repeats 5 --seed 42 \
  --csv benchmark.csv --report report.md
```

Параметры:

| Параметр | Значение по умолчанию |
|---|---|
| `--sizes` | `100 1000 10000` |
| `--repeats` | `5` (минимум по заданию) |
| `--seed` | `42` |
| `--algorithms` | `selection quick` |
| `--inputs` | все пять наборов |
| `--max-size АЛГОРИТМ=N` | без ограничений |
| `--csv` | `benchmark.csv` |

CSV содержит столбцы: `algorithm, input, n, repeats, min_s, max_s, median_s, mean_s`

### Сопоставление с ожидаемой сложностью

Если время растёт как `f(n)`, то при переходе от `n1` к `n2` отношение `T(n2)/T(n1)` должно быть близко к `f(n2)/f(n1)`.

| Переход | Ожидание для O(n²) | Ожидание для O(n log n) |
|---|---|---|
| 100 → 1 000 | ×100 | ×15 |
| 1 000 → 10 000 | ×100 | ×13 |


- рост `selection_sort` при увеличении n в 10 раз близок к ×100, что подтверждает O(n²); время почти не зависит от типа входа;
- рост `quick_sort` близок к ×13–15, что подтверждает O(n log n); на `many_duplicates` он быстрее остальных из-за трёхстороннего разбиения;
- на `n = 100` время измеряется микросекундами и содержит заметный шум, поэтому основной вывод строится по размерам 1 000 и 10 000 и по показателю `k`;

## Консольный интерфейс

```bash
algopack pow 2 10 --method both        # быстрая степень, оба способа и сверка результатов
algopack sort 5 -3 9 0 -3 -a quick     # сортировка чисел
algopack generate random 10   # генератор набора
algopack queue add 1 add 2 pop next len bool   # цепочка операций над очередью
algopack benchmark   # замеры, CSV
```
